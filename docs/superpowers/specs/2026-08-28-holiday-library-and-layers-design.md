## 2. 目标与非目标

### 2.1 目标

1. 移除业务模型、模板和渲染流程中固定的“中国节假日”和“日本节假日”槽位。
2. 在 Monthloom 内维护一套跨项目、跨年份累计的全局节假日资料库，作为唯一事实来源（SSOT）。
3. 系统默认提供中国和日本两套节假日日历，并通过现有数据源便捷同步。
4. 允许用户创建其他地区或自定义用途的节假日日历。
5. 允许 API 同步、Monthloom JSON 导入和人工编辑共同更新全局资料库。
6. 让模板保存节假日图层及其视觉样式，但不复制真实节假日记录。
7. 让 Main、Mini、年度预览和正式 SVG 导出使用同一份节假日解析结果。
8. 在数据跨越三个自然年且未来数据尚未公布时，准确表达“未知”，而不是猜测或阻止用户工作。
9. 保持使用流程低负担：项目备份自动携带完整节假日资料库，不要求用户选择地区或年份。

### 2.2 非目标

- 不建设云端账号、云同步或多人协作系统。
- 不为任意第三方节假日 API 提供通用网络连接器。
- 不自动推断某个周末、工作日或日期是否应该是假期。
- 不检测节假日名称或角标之间的视觉重叠。
- 不兼容当前开发版本的旧快照、旧数据库结构或旧固定字段。

## 3. 领域模型

### 3.1 节假日资料库（Holiday Library）

Monthloom 在浏览器 IndexedDB 中维护的全局资料库。它独立于任何项目，保存所有节假日日历、跨年份记录、覆盖状态、同步基线和人工覆盖。

资料库是节假日数据的 SSOT。任何项目打开、切换目标年份、预览或导出时，都从该资料库读取当前有效数据。修改资料库会同步影响所有引用该数据的项目。

### 3.2 节假日日历（Holiday Calendar）

资料库中的长期数据集合，例如：

- 中国公众假期
- 日本公众假期
- 香港公众假期
- 美国联邦假期
- 公司内部休假日

节假日日历不是某一年的文件。它可以持续累计多个年份的数据，并拥有稳定 ID、名称、来源能力和覆盖状态。

系统初始化时创建两套内置日历：

- 中国公众假期：固定系统 ID，具有中国数据源同步能力。
- 日本公众假期：固定系统 ID，具有日本数据源同步能力。

内置日历不能删除，可以不加入模板或在模板中关闭。用户创建的日历没有默认远程同步能力，但可以通过 Monthloom JSON 和人工编辑维护。

### 3.3 节假日记录（Holiday Record）

一条记录描述一个日期的特殊状态：

- `date`：有效的 `LocalDate`。
- `type`：`holiday` 或 `workday`。
- `name`：可选名称。

`holiday` 表示假日；`workday` 表示调休工作日。日期运算必须继续遵守 Monthloom 的 UTC / `LocalDate` 约束。

同一个节假日日历在同一个日期只能产生一个有效记录。

### 3.4 节假日图层（Holiday Layer）

模板中的显示规则。每个图层引用一套全局节假日日历，并保存 Main 与 Mini 的视觉配置。

一对一约束的准确范围是：

- 在同一个模板中，一个节假日日历最多对应一个节假日图层。
- 一个节假日图层只能引用一个节假日日历。
- 同一个全局节假日日历可以被多个模板分别引用；每个模板拥有自己的图层样式。

图层顺序具有业务含义：越靠后的图层，日期文字颜色优先级越高。

## 4. SSOT 与数据归属

### 4.1 全局资料库保存

- 节假日日历元数据
- 远程同步或导入得到的基线记录
- 人工新增、修改和删除形成的覆盖
- 数据覆盖范围与确认状态
- 最近同步结果与时间

### 4.2 模板保存

- 有序节假日图层
- 图层启用状态
- 被引用节假日日历的稳定 ID
- Main 显示配置
- Mini 显示配置

模板不保存真实节假日记录。

### 4.3 项目保存

- 目标年份
- 当前编辑器文档和模板配置
- 模板中的节假日图层引用

项目运行时不保存节假日记录副本。重新打开项目时，始终读取全局资料库中的当前有效数据。因此资料库中的同步或人工修改会影响所有旧项目。

## 5. 同步基线与人工覆盖

为了同时支持远程同步和人工维护，每个日期的有效状态由“数据源基线 + 人工覆盖”计算。

### 5.1 基线

基线来自：

- 中国或日本远程同步适配器
- 原始提供方 JSON 导入适配器
- Monthloom JSON 导入

重新同步或重新导入可以更新基线。

### 5.2 人工覆盖

人工操作优先于基线：

- 人工修改：有效记录使用人工版本，后续同步不得静默覆盖。
- 人工新增：即使基线没有该日期，也生成有效记录。
- 人工删除基线记录：保存删除覆盖；后续同步不得让该记录自动重新出现。
- 恢复为数据源内容：删除人工覆盖，重新使用当前基线。

界面必须标识记录是“数据源记录”“人工修改”还是“人工新增”。

### 5.3 同步或导入冲突

任何同步和导入都先计算变更集，再在一笔事务中写入：

- 新基线可以新增或更新未被人工覆盖的记录。
- 人工覆盖保持不变。
- 请求失败、超时、格式异常或事务失败时，资料库保持原状。

## 6. 覆盖范围与未知未来数据

目标年份 `Y` 的正式输出会使用跨三个自然年的日期：

- `Y-1` 年 12 月
- `Y` 年 1 月至 12 月
- `Y+1` 年 1 月至 2 月

系统不能因为记录列表中没有某个日期，就断言该日期已被完整检查。每套节假日日历需要独立维护覆盖范围。

覆盖状态至少区分：

- 已确认：数据源或用户确认该日期范围的数据完整。
- 未确认：存在部分记录，但不能证明整个范围完整。
- 未知：该日期范围没有可用信息，或未来安排尚未公布。

对于中国下一年 1–2 月尚未公布的情况，应显示非阻塞覆盖提示。未知范围不阻止模板编辑、预览或正式导出，Monthloom 也不得推测未来安排。

按年份同步成功后，该同步适配器可以把相应年份标记为已确认。人工维护的日历只有在用户明确确认一个年份或日期范围后，才能把该范围标记为已确认。

## 7. 数据获取与维护

### 7.1 中国同步

中国内置日历使用现有 Timor 数据格式适配器。用户选择一个或多个年份进行同步。年度端点返回假日和调休工作日数据，例如：

- <https://timor.tech/api/holiday/year/2026/>

同步只更新所选年份的基线，不删除其他年份的数据，也不覆盖人工修改。

### 7.2 日本同步

日本内置日历使用现有 Holidays JP 数据格式适配器。官方接口提供年度 JSON：

- <https://holidays-jp.github.io/api/v1/2026/date.json>
- <https://holidays-jp.github.io/>

同步只更新返回范围内的基线，不覆盖人工修改。数据源尚未提供的未来年份保持未知。

### 7.3 原始提供方 JSON

中国和日本内置日历继续支持导入现有提供方格式，并通过对应适配器转换为统一内部模型。用户不需要手工把现有 API 响应整理成 Monthloom JSON。

### 7.4 人工维护

所有节假日日历都支持：

- 添加单个日期
- 添加连续日期范围
- 修改类型和名称
- 删除记录
- 恢复数据源记录
- 按年份筛选和检查
- 将年份或日期范围标记为已确认

### 7.5 Monthloom JSON

Monthloom 定义稳定的用户交换格式，用于单套节假日日历的导入和导出。JSON 是批量交换与备份手段，不是普通用户维护数据的唯一入口。

最小结构如下：

```json
{
  "format": "monthloom-holidays",
  "version": 1,
  "calendar": {
    "id": "cn-public-holidays",
    "name": "中国公众假期"
  },
  "coverage": [
    {
      "start": "2027-01-01",
      "end": "2027-12-31",
      "status": "confirmed"
    }
  ],
  "records": [
    {
      "date": "2027-01-01",
      "type": "holiday",
      "name": "元旦"
    },
    {
      "date": "2027-02-06",
      "type": "workday"
    }
  ]
}
```

导入规则：

- 严格验证格式版本、稳定 ID、日期和记录类型。
- 文件内不得包含重复日期。
- 有确认覆盖范围时，导入内容替换该范围内的基线，但保留人工覆盖和范围外数据。
- 没有确认覆盖范围时，只按日期新增或更新基线，不删除其他记录，也不声称范围完整。
- 整个文件验证通过后才写入，不允许部分导入。

项目备份包使用内部资料库快照格式保存完整基线、人工覆盖和来源信息，不等同于上述面向用户的单日历交换格式。

## 8. 模板图层与显示配置

### 8.1 通用图层配置

每个节假日图层包含：

- 稳定图层 ID
- 被引用节假日日历 ID
- 启用状态
- 在模板中的顺序
- Main 配置
- Mini 配置

把节假日日历加入模板时创建对应图层。已存在于当前模板中的日历不能重复添加。从模板移除图层不会删除全局资料库数据。

模板加载时优先按节假日日历稳定 ID 自动关联全局资料库。如果找不到相同 ID，图层保持缺失状态，并允许用户从资料库手动选择一个尚未被当前模板使用的日历重新关联。手动关联会更新模板中的日历引用，后续保存该模板时保留新的稳定 ID。

### 8.2 Main 配置

Main 图层可以配置：

- 是否显示节假日名称
- 名称的字体、字号、字重、颜色、透明度和位置
- 假日角标是否启用
- 调休工作日角标是否启用
- 两种角标各自的类型、内容或图片资源、尺寸、颜色、透明度和位置；检查器仅展示当前角标类型适用的字段
- 是否影响日期文字颜色
- 假日日期颜色
- 调休工作日日期颜色

只有 `holiday` 记录且存在 `name` 时才渲染节假日名称。`workday` 记录不渲染节假日名称，但可以渲染调休角标并影响日期颜色。

### 8.3 Mini 配置

Mini 不提供节假日名称能力，也不显示任何名称相关设置。

Mini 图层可以配置：

- 假日角标是否启用
- 调休工作日角标是否启用
- 两种角标各自的类型、内容或图片资源、尺寸、颜色、透明度和位置；检查器仅展示当前角标类型适用的字段
- 是否影响日期文字颜色
- 假日日期颜色
- 调休工作日日期颜色

Main 和 Mini 共用同一套节假日记录和同一图层顺序，但视觉配置相互独立。

## 9. 解析、优先级与渲染

新增集中的节假日解析模块。它接收：

- 目标日期范围
- 有序且启用的节假日图层
- 全局资料库中这些图层引用的有效记录

它输出每个日期的：

- 命中的图层记录
- Main 名称和角标表现
- Mini 角标表现
- Main 最终日期颜色
- Mini 最终日期颜色
- 覆盖诊断

日期颜色解析顺序：

1. 先使用普通日期、星期日或星期六的基础颜色。
2. 按模板中的节假日图层顺序从前到后处理。
3. 图层命中日期且启用“影响日期颜色”时，使用该记录类型对应的颜色覆盖当前颜色。
4. 因此越靠后的图层优先级越高。

名称和角标不采用后图层覆盖前图层的规则。所有启用且命中的图层都生成各自的名称或角标。用户通过图层样式和位置处理视觉布局；系统不检测、不提示重叠，也不自动合并内容。

`layoutMain` 与 `layoutMini` 继续负责所有几何计算。SVG materializer、serializer、预览和批量导出不得重新解释节假日优先级或重新计算布局。

## 10. UI/UX 设计

### 10.1 全局节假日资料库入口

工作区提供独立“节假日资料库”入口，不把数据维护混入模板检查器。

管理视图采用左侧日历列表、右侧详情：

- 左侧显示内置和用户创建的节假日日历。
- 每项显示已有年份、记录数量和当前目标年份覆盖状态。
- 顶部提供“新增节假日日历”。
- 中国、日本内置项提供“同步”。
- 自定义项提供 Monthloom JSON 导入。
- 所有项都支持人工维护。

右侧按年份显示记录表：

- 日期
- 假日或调休工作日类型
- 名称
- 来源
- 数据源、人工修改或人工新增状态
- 编辑与删除操作

表格上方提供年份切换、同步、导入、添加日期、添加日期范围和导出 Monthloom JSON。

同步和导入先展示新增、修改、删除摘要。完成后保持列表位置和当前年份，避免用户丢失上下文。

### 10.2 模板编辑器图层列表

左侧图层列表增加可折叠“节假日”分组和添加按钮。

每个节假日图层支持：

- 启用或关闭
- 展开或折叠
- 拖动排序
- 可通过键盘操作的上移和下移
- 从当前模板移除

添加时从全局资料库选择尚未加入当前模板的节假日日历。列表明确说明“越靠后的节假日图层，日期颜色优先级越高”。

缺失日历的图层提供“关联资料库”操作。Monthloom 先尝试稳定 ID 自动匹配；无法匹配时才要求用户选择，避免每次加载模板都重复绑定。

Main 编辑模式展开：

- 节假日名称
- 假日角标
- 调休角标
- 日期颜色

Mini 编辑模式展开：

- 假日角标
- 调休角标
- 日期颜色

选择子项后复用当前右侧检查器的排版、位置、颜色和角标编辑模式。点击画布中的实际名称或角标，也应选择对应图层子项。

如果当前目标范围没有对应数据，图层仍然可编辑，并显示“当前范围暂无数据”或覆盖状态。缺少实例不是错误，也不禁用样式设置。

### 10.3 删除规则

- 内置中国、日本日历不能删除。
- 用户创建且未被任何模板引用的日历可以删除。
- 用户创建且仍被模板引用的日历不能直接删除；界面应说明引用情况，用户需先从相关模板移除图层。

## 11. 持久化、项目包与模板包

### 11.1 IndexedDB

全局资料库使用独立持久化表保存日历、基线记录、人工覆盖、覆盖范围和同步状态。所有多实体写入继续使用单个 Dexie `rw` 事务。

### 11.2 模板包

模板包保存节假日图层和样式，不包含任何真实节假日记录。目标环境缺少被引用日历时，保留图层设计并显示“缺少节假日日历”；创建或导入同 ID 日历后自动恢复显示，或者由用户手动关联另一套尚未被当前模板使用的日历。

### 11.3 项目包

导出 `.monthloom` 项目包时，自动附带当前 Monthloom 中的完整节假日资料库，而不是只附带项目引用的数据。用户不需要选择地区、年份或是否附带。

导出界面固定说明：

> 项目包将包含 Monthloom 中的完整节假日资料库，以便在其他设备上继续使用。

导入项目包时自动把附带资料合并进目标设备 SSOT：

- 目标设备没有的日历、年份和记录自动加入。
- 相同日历 ID 的名称和元数据以目标设备为准。
- 目标设备已有的人工覆盖优先。
- 两边存在不同人工修改时保留目标设备版本，不阻塞导入。
- 导入完成后显示新增数量和跳过的人工冲突数量。

项目运行时仍只读取全局资料库；项目包中的资料是迁移载体，不是项目级冻结快照。

## 12. 错误处理与诊断

- 远程同步失败：保留原数据，显示可操作的失败原因。
- 导入格式错误：拒绝整个文件，不部分写入。
- 事务失败：不留下部分写入状态。
- 图层引用的日历不存在：保留图层设计并显示缺失状态。
- 当前输出范围覆盖不足：显示非阻塞提示，允许预览和导出。
- 人工修改与同步冲突：人工修改保持有效，并提供恢复数据源的操作。
- 多图层名称或角标重叠：不检测、不提示。

诊断文案需要区分“数据未知”“同步失败”“引用缺失”和“文件无效”，不能统一显示为导入错误。

## 13. 开发阶段兼容策略

当前应用仍处于开发阶段，本设计采用干净切换：

- 直接删除固定 China/Japan 业务类型、模板字段、工作区槽位和渲染分支。
- 直接采用新的资料库、动态图层和快照结构。
- 不实现旧项目快照解析器。
- 不实现 IndexedDB 数据迁移器。
- 不保留兼容字段或双写逻辑。
- 实现阶段允许一次性清空或重建本地开发数据库。
- 现有 tests、fixtures 和开发文档直接更新到新模型。

## 14. 测试策略

### 14.1 领域与解析

- 同一日历同一日期只有一条有效记录。
- 同步基线、人工修改、人工新增和人工删除的优先级。
- 恢复数据源内容。
- 多图层日期颜色按顺序覆盖。
- 未启用颜色影响的图层不改变日期颜色。
- 名称和角标同时保留，不因颜色优先级被覆盖。
- 跨 `Y-1`、`Y`、`Y+1` 的范围与覆盖诊断。
- Mini 永远不生成节假日名称。
- 同一模板中日历与图层的一对一约束。

### 14.2 适配器与输入

- 中国提供方格式解析。
- 日本提供方格式解析。
- Monthloom JSON 严格校验。
- 重复日期、非法日期、未知版本和非法记录类型。
- 同步或导入不覆盖人工修改。
- 同步失败不改变现有数据。

### 14.3 持久化与备份

- 资料库多实体写入原子性。
- 项目包携带完整资料库。
- 项目包导入的非破坏性合并。
- 目标设备人工冲突保留和摘要。
- 模板包不包含节假日记录。

### 14.4 渲染与正式输出

- Main 多图层名称和角标生成。
- Main 假日与调休日期颜色。
- Mini 角标与日期颜色，且没有名称。
- 相邻月份透明度仍作用于节假日元素。
- 预览与正式 SVG 使用相同解析结果。
- 正式导出仍严格生成 13 个 Main 与 15 个 Mini，共 28 个 SVG。

按照项目规范，不为纯视觉 UI 修改增加单元测试；交互状态和共享逻辑只在存在实际行为风险时测试。

## 15. 验收标准

1. 代码中不再存在业务意义上的固定 China/Japan 数据槽、模板字段或渲染分支。
2. 新安装的 Monthloom 拥有中、日两套内置节假日日历及默认模板图层。
3. 中国、日本可以按数据源能力同步；所有日历都可以人工维护。
4. 人工修改、增加和删除不会被后续同步静默覆盖。
5. 用户可以创建其他地区或自定义节假日日历，并在模板中创建唯一对应图层。
6. 切换目标年份时自动复用全局资料库中已累计的数据。
7. 未知的未来范围只产生非阻塞提示。
8. Main 支持名称、假日/调休角标和日期颜色；Mini 不显示名称，只支持角标和日期颜色。
9. 多图层日期颜色由后图层覆盖前图层，名称和角标全部保留。
10. 系统不提示名称或角标重叠。
11. 模板保存样式但不保存真实记录。
12. 模板优先按稳定 ID 自动关联日历；匹配失败时允许用户手动关联。
13. 项目包自动携带并恢复完整节假日资料库，不要求用户选择范围。
14. 全局资料库更新后，所有引用它的项目同步变化。
15. Main、Mini、预览和正式导出消费同一节假日解析结果。
16. 不包含任何旧数据兼容或迁移实现。
